# Faceit Finder Bot

Telegram-бот на Python, который по ссылке на Steam-профиль показывает
статистику игрока на Faceit по CS2.

> **Статус проекта:** основной сценарий работает — бот принимает ссылку на
> Steam-профиль, находит игрока Faceit и отправляет статистику CS2 с
> inline-кнопками профиля и обновления. Также поддерживается сравнение
> двух игроков по ключевым показателям.

## Стек

- Python 3.11+
- aiogram 3 (long polling)
- httpx (асинхронные HTTP-запросы)
- pydantic-settings (конфигурация из `.env`)

## Запуск

### 1. Создать виртуальное окружение

Windows:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

Для запуска тестов установите dev-зависимости:

```bash
pip install -r requirements-dev.txt
```

### 3. Настроить окружение

Скопируйте `.env.example` в `.env`:

```powershell
Copy-Item .env.example .env
```

Linux/macOS:

```bash
cp .env.example .env
```

Заполните параметры:

| Переменная | Обязательность | Описание |
|---|---|---|
| `BOT_TOKEN` | Да | Токен бота от [@BotFather](https://t.me/BotFather) |
| `STEAM_API_KEY` | Для коротких ссылок и Steam-статистики | Ключ Steam Web API для ссылок `/id/...`, vanity-имён, часов CS2 и VAC-статуса |
| `FACEIT_API_KEY` | Для статистики | Ключ Faceit Data API v4 |
| `RATE_LIMIT_REQUESTS` | Нет | Сколько действий пользователя разрешено за окно (по умолчанию `10`) |
| `RATE_LIMIT_WINDOW_SECONDS` | Нет | Длина окна лимита в секундах (по умолчанию `60`) |
| `RATE_LIMIT_HEAVY_WEIGHT` | Нет | Вес сравнения и refresh; обычный поиск весит `1` (по умолчанию `2`) |
| `FACEIT_MAX_CONCURRENCY` | Нет | Максимум одновременных HTTP-запросов к Faceit (по умолчанию `5`) |
| `FACEIT_MAX_REQUESTS_PER_SECOND` | Нет | Проактивный лимит исходящих запросов Faceit в секунду, token bucket (по умолчанию `4`) |
| `FACEIT_RATE_LIMIT_COOLDOWN_SECONDS` | Нет | Минимальная глобальная пауза после 429 (по умолчанию `30`) |
| `FACEIT_RATE_LIMIT_COOLDOWN_MAX_SECONDS` | Нет | Потолок глобальной паузы после 429 (по умолчанию `300`) |
| `FACEIT_CACHE_MAX_ENTRIES` | Нет | Максимум записей TTL/LRU-кэша Faceit (по умолчанию `2500`) |
| `FACEIT_NEGATIVE_CACHE_TTL_SECONDS` | Нет | Сколько секунд помнить 404 по поиску игрока (по умолчанию `60`) |
| `REFRESH_COOLDOWN_SECONDS` | Нет | Минимальный интервал повторного refresh одного игрока (по умолчанию `60`) |

`BOT_TOKEN` обязателен для запуска бота. Прямые ссылки
`/profiles/<SteamID64>` и голый SteamID64 разрешаются без `STEAM_API_KEY`.
Без `FACEIT_API_KEY` бот запускается, но на ссылки отвечает сообщением о
ненастроенной проверке Faceit.

### 4. Запустить бота

Из корня проекта:

```bash
python -m bot.main
```

Бот запустится в режиме long polling. Для остановки нажмите `Ctrl+C`.

## Что умеет бот

- `/start` — приветствие с кнопками быстрого доступа и постоянным меню.
- `/help` — справка по использованию.
- `/cancel` — отменить пошаговый ввод и вернуться в меню.
- Постоянное Reply-меню внизу чата:
  - «🔍 Найти игрока»;
  - «⚔️ Сравнить игроков»;
  - «ℹ️ Помощь».
- «⚔️ Сравнить игроков» запускает пошаговый сценарий:
  - бот просит ссылку на первого игрока;
  - затем на второго;
  - на каждом шаге доступна кнопка «Отмена».
- `/compare <url1> <url2>` — быстрое сравнение двух игроков Faceit.
  Дополнительно можно просто отправить две ссылки на Steam-профили
  одним сообщением.
- Любое сообщение со ссылкой на Steam-профиль:
  - `/profiles/<SteamID64>`;
  - `/id/<vanity>` (нужен `STEAM_API_KEY`).
- В `/compare` и пошаговом сравнении дополнительно принимаются голые
  SteamID64 и vanity-имена.
- Если у игрока нет аккаунта Faceit с CS2, бот отвечает:
  `У этого игрока нет Faceit-аккаунта с CS2`.
- Сообщение со статистикой содержит:
  - шапку: ник, флаг страны, уровень и текущий ELO, максимальный ELO
    (если API его отдаёт) и ссылку на профиль;
  - место в рейтинге страны и региона Faceit;
  - общую статистику: матчи, винрейт, K/D, HS%, лучшую и текущую серию;
    рядом с винрейтом и K/D показано значение за последние 20 матчей
    со стрелкой ↑/↓;
  - форму за последние 20 матчей: средние K/D, ADR, K/R, килы, винрейт
    и результаты последних 10 матчей (новые слева);
  - последние 5 матчей: карта, счёт, K/D/A и изменение ELO;
  - таблицу всех карт пула с винрейтом и числом матчей, отсортированную
    по винрейту. Карты с 30+ матчами помечаются как лучшие (🏆) или
    слабые (📉) относительно общего винрейта, остальные — ▫️, карты
    с меньшей выборкой — значком ⚠️;
  - Steam: часы в CS2 и статус VAC-бана (при наличии `STEAM_API_KEY`
    и открытом профиле);
  - время обновления внизу сообщения.
- Сообщение со сравнением содержит:
  - шапку обоих игроков: ник, флаг, уровень и ELO;
  - ключевые показатели: ELO, винрейт, K/D, HS%, ADR, текущую серию
    и часы в CS2;
  - лучший показатель каждой метрики выделяется жирным шрифтом и 🏆,
    рядом показана разница `Δ` (первый игрок минус второй);
  - отдельные кнопки профилей обоих игроков и «Обновить сравнение».
- Если при сравнении один из игроков не найден, бот сообщает, с какой
  стороны проблема; при 429 выводится отдельное сообщение о лимите Faceit,
  а если известно `Retry-After` — ещё и время повтора.
- Отсутствующие в ответе API поля и блоки просто пропускаются, сообщение
  обрезается до лимита Telegram в 4096 символов.
- Inline-кнопки:
  - на стартовом экране — «Найти игрока», «Сравнить игроков», «Помощь»;
  - «Открыть профиль на Faceit»;
  - «Обновить» — точечно обновляет данные одного игрока, не затрагивая
    кэш остальных; повторное нажатие в течение 60 секунд после загрузки
    (включая первичный показ профиля) отвечает
    «Данные уже свежие, обновлены X сек назад»;
  - «Обновить сравнение» — то же для обоих участников сравнения; cooldown
    проверяется по каждому игроку отдельно, поэтому перестановка A/B или
    замена второго участника не обходит ограничение;
  - «Отмена» — сбрасывает пошаговый сценарий.

`FaceitClient` кэширует ответы на 5 минут, но не более 2500 записей.
Вытеснение — LRU: давно не использованные записи уходят первыми. Протухшие
записи удаляются при чтении, раз в 100 операций записи и перед вытеснением,
поэтому они не накапливаются. Замеры репрезентативных ответов (рекурсивный
`sys.getsizeof`): lifetime с 20 сегментами — ~15 КБ, recent matches на 21
матч — ~33 КБ, match details на 2 команды по 5 игроков — ~9 КБ. Один
просмотр профиля занимает до ~11 записей (~124 КБ), сравнение — до ~22
записей (~249 КБ). Лимит 2500 записей — это примерно 227 просмотров или
114 сравнений и ~27 МБ; прежние 6600 записей давали ~71 МБ. Одинаковые
одновременные запросы объединяются (single-flight). Исходящие HTTP-запросы
проходят token bucket со скоростью `FACEIT_MAX_REQUESTS_PER_SECOND`
(по умолчанию 4 запроса/сек, всплеск не больше секунды) до семафора
(по умолчанию 5 одновременно), поэтому ожидание токена не занимает слот
параллелизма. Ответы из кэша токены не расходуют. После 429 повторов нет:
клиент сразу включает глобальную паузу `max(Retry-After, 30 секунд)`
с потолком 300 секунд, выбрасывает `FaceitRateLimit` и перестаёт обращаться
к сети; `sleep` и повторная попытка для 429 отсутствуют. Экспоненциальный
retry остаётся только для ответов 5xx. Кэшированные ответы во время паузы
продолжают выдаваться, а в сообщении пользователю указывается известное
время повтора. Детали завершённых матчей не тегируются игроком, поэтому
refresh профиля не запрашивает их повторно. 404 по поиску игрока помнится
60 секунд отдельным негативным кэшем и сбрасывается кнопкой «Обновить».
При закрытии клиент отменяет и дожидается незавершённых single-flight задач,
затем закрывает HTTP-соединения. Один экземпляр клиента создаётся в
`bot/main.py` и передаётся хендлерам через `Dispatcher`.

Действия, которые могут тратить квоту Faceit, ограничены по пользователю:
по умолчанию 10 единиц за 60 секунд, где сравнение и refresh стоят 2,
а обычный поиск — 1. `/start`, `/help`, `/cancel`, кнопки меню и текстовые
команды отмены FSM («Отмена», «отмена», `/cancel`) не лимитируются.
`RateLimitMiddleware` подключён к `dp.message.outer_middleware` и
`dp.callback_query.outer_middleware`, а `refresh_cooldown` и `faceit_client`
передаются через workflow data `Dispatcher`. При превышении бот один раз
предупреждает о лимите и дальше молча пропускает события до конца окна;
callback при этом всегда получает ответ, чтобы не оставался спиннер.

Пошаговое сравнение использует встроенный FSM aiogram с `MemoryStorage`:
состояние хранится только в памяти процесса, не требует БД и сбрасывается
при рестарте бота.

## Возможные доработки

1. Хранить историю матчей и строить графики прогресса.
2. Кэшировать профили в базе данных и поддержать несколько игр Faceit.
3. Добавить сравнение более чем двух игроков и общую сводную таблицу.

# Faceit Finder Bot — полное описание проекта

## 1. Что это за проект

**Faceit Finder Bot** — Telegram-бот на Python, который по ссылке на Steam-профиль находит игрока на Faceit и присылает подробную статистику по CS2.

Основной сценарий:

1. Пользователь отправляет боту ссылку на Steam-профиль.
2. Бот извлекает SteamID64.
3. Через Faceit Data API v4 находит Faceit-аккаунт, привязанный к этому SteamID64.
4. Параллельно загружает lifetime-статистику, последние матчи, рейтинги, детали матчей и данные Steam.
5. Считает производные показатели: винрейт, K/D, форму, серии, карты, изменения ELO.
6. Формирует HTML-сообщение для Telegram и inline-клавиатуру.

Проект не хранит данные в базе: он работает как stateless-сервис с in-memory кэшем ответов Faceit API.

## 4. Конфигурация и запуск

### Переменные окружения

Файл `.env` читается через `pydantic-settings`:

| Переменная | Обязательна | Что делает |
|---|---|---|
| `BOT_TOKEN` | Да | Токен Telegram-бота от @BotFather |
| `STEAM_API_KEY` | Нет | Нужен для vanity-ссылок `/id/...`, часов CS2 и VAC-статуса |
| `FACEIT_API_KEY` | Нет | Нужен для запросов статистики Faceit |

Особенности:

- Без `BOT_TOKEN` приложение не запустится.
- Без `STEAM_API_KEY`:
  - прямые ссылки `/profiles/<SteamID64>` работают;
  - короткие ссылки `/id/<vanity>` не разрешаются;
  - блок Steam не выводится.
- Без `FACEIT_API_KEY` бот запускается, но на любую ссылку отвечает:
  `Проверка Faceit не настроена: добавь FACEIT_API_KEY в .env.`
- Секреты хранятся в `SecretStr`, `.env` исключён через `.gitignore`.

### Запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m bot.main
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## 5. Пользовательский сценарий

### Команды

- `/start` — приветствие и краткая инструкция.
- `/help` — справка по использованию.

### Обработка ссылки

Бот реагирует на текстовые сообщения, в которых есть `http(s)`-ссылка.

Поддерживаются:

- `https://steamcommunity.com/profiles/<SteamID64>`;
- `https://steamcommunity.com/id/<vanity>`;
- ссылки с `http`, `www`, завершающим слэшем, query-параметрами и якорем.

Дополнительно `parse_steam_input()` умеет разбирать:

- голый SteamID64;
- голое vanity-имя;
- отклоняет числовые строки, не похожие на SteamID64, чтобы не делать лишний запрос в Steam.

Важный нюанс текущей реализации: в чате `handle_link()` сначала ищет именно URL. Поэтому голый SteamID64 или vanity-имя без ссылки до резолвера не дойдут — бот ответит «Не вижу ссылки». Резолвер их поддерживает, но обработчик сообщения требует URL.

### Ответы на ошибки

- Нет ссылки → `Не вижу ссылки в сообщении. 🤔`
- Не удалось получить SteamID64 → `Не удалось получить SteamID64 по этой ссылке. 🤔`
- Нет Faceit-аккаунта с CS2 → `У этого игрока нет Faceit-аккаунта с CS2`
- Нет `FACEIT_API_KEY` → сообщение о ненастроенной проверке.
- Faceit вернул 429 → `Faceit временно ограничил количество запросов. Попробуй чуть позже.`
- Другая ошибка Faceit → `Не удалось получить статистику Faceit. Попробуй ещё раз позже.`

### Inline-кнопки

Под сообщением:

- **«Открыть профиль на Faceit»** — ссылка на профиль;
- **«Обновить»** — callback `refresh:<SteamID64>`.

При обновлении:

1. Проверяется корректность SteamID64.
2. Очищается весь кэш Faceit.
3. Статистика загружается заново.
4. Сообщение редактируется через `edit_text`.
5. Если Telegram отвечает `message is not modified`, ошибка игнорируется.
6. При другой ошибке редактирования бот отправляет новое сообщение.

## 6. Архитектура и поток данных

```text
Telegram Update
      │
      ▼
handlers.handle_link()
      │
      ├── _extract_url()                 # первая ссылка из текста
      │
      ├── resolve_steam_id()             # SteamID64
      │       └── Steam Web API          # только для vanity
      │
      └── _load_player_stats()
              │
              ├── Faceit: GET /players?game=cs2&game_player_id=...
              │
              ├── asyncio.gather(...)
              │       ├── lifetime stats
              │       ├── recent matches (limit=21)
              │       ├── Steam stats
              │       ├── region ranking
              │       └── country ranking
              │
              ├── _load_match_details()  # детали первых 5 матчей
              │
              └── build_player_stats()
                      │
                      ▼
              format_player_stats()
              build_player_keyboard()
                      │
                      ▼
              message.answer() / edit_text()
```

Все независимые запросы выполняются параллельно через `asyncio.gather(..., return_exceptions=True)`. Это позволяет показывать частичную статистику, если, например, рейтинг или Steam недоступны.

## 7. Подробно по модулям

### 7.1. `config.py`

Содержит `Settings` на базе `BaseSettings`.

- `.env` ищется рядом с `config.py`.
- Пустые переменные игнорируются.
- Неизвестные переменные игнорируются.
- `bot_token` — обязательный `SecretStr`.
- `steam_api_key`, `faceit_api_key` — необязательные `SecretStr`.
- Глобальный объект `settings` создаётся при импорте.

### 7.2. `bot/main.py`

Отвечает за запуск приложения.

- Настраивает логирование.
- Предупреждает, если не заданы Steam/Faceit ключи.
- Создаёт `FaceitClient` только при наличии `FACEIT_API_KEY`.
- Создаёт `Bot` с `ParseMode.HTML` по умолчанию.
- Создаёт `Dispatcher`, подключает `router` и кладёт `faceit_client` в DI-контейнер.
- Удаляет webhook с `drop_pending_updates=True`.
- Запускает long polling.
- В `finally` закрывает сессию бота и HTTP-клиент Faceit.

### 7.3. `bot/handlers.py`

Главный сценарийный модуль.

Ключевые функции:

- `_extract_url()` — находит первую ссылку и обрезает хвостовую пунктуацию.
- `_unwrap_stats_response()` — разбирает результаты `gather` для обязательных запросов.
- `_optional_payload()` — безопасно обрабатывает необязательные ответы.
- `_load_match_details()` — загружает детали первых пяти матчей по `match_id`.
- `_load_player_stats()` — основной оркестратор загрузки.
- `_build_message()` — собирает текст и клавиатуру.
- `handle_start()`, `handle_help()`, `handle_link()`, `handle_refresh()`.

Логика `_load_player_stats()`:

1. `get_player_by_steam_id(steam64)`.
2. Если игрок не найден — `None`.
3. Из профиля достаются `player_id`, `region`, `country`.
4. Параллельно запускаются:
   - lifetime-статистика;
   - последние 21 матч;
   - Steam-статистика;
   - рейтинг региона, если известен регион;
   - рейтинг страны, если известны регион и страна.
5. Если и lifetime, и recent упали с ошибкой — ошибка пробрасывается.
6. Если упал только один из них — бот показывает то, что удалось загрузить.
7. Рейтинг и Steam считаются необязательными: их ошибки только логируются.
8. Загружаются детали первых пяти матчей.
9. Вызывается `build_player_stats()`.

Особенности:

- Перед загрузкой бот отправляет `typing`-action.
- Для обычного сообщения используется `answer(..., disable_web_page_preview=True)`.
- Для refresh — `edit_text`, с fallback на новое сообщение.
- Если при refresh игрок исчез, сообщение заменяется на «нет Faceit-аккаунта», клавиатура убирается.

### 7.4. `bot/faceit.py`

Асинхронный клиент Faceit Data API v4.

База:

```text
https://open.faceit.com/data/v4
```

Авторизация:

```text
Authorization: Bearer <FACEIT_API_KEY>
```

Используемые эндпоинты:

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `get_player_by_steam_id` | `GET /players?game=cs2&game_player_id=<steam64>` | Поиск игрока по SteamID64 |
| `get_lifetime_stats` | `GET /players/{player_id}/stats/cs2` | Lifetime-статистика и сегменты по картам |
| `get_recent_matches` | `GET /players/{player_id}/games/cs2/stats?limit=N` | Последние матчи |
| `get_player_ranking` | `GET /rankings/games/cs2/regions/{region}/players/{player_id}` | Позиция в рейтинге региона; опционально `country` |
| `get_match_details` | `GET /matches/{match_id}` | Счёт и составы матча |

Модели Pydantic:

- `FaceitGameProfile`
- `FaceitPlayer`
- `FaceitStatsSegment`
- `FaceitLifetimeStats`
- `FaceitMatch`
- `FaceitRecentMatches`
- `FaceitPlayerRanking`
- `FaceitMatchDetails`

Все модели используют `extra="ignore"`, то есть новые поля API не ломают парсинг.

#### Ретраи

- По умолчанию `max_retries=3`, то есть до 4 попыток.
- На `429`:
  - используется `Retry-After`, если он задан в секундах;
  - иначе экспоненциальная задержка `0.5 * 2^attempt`.
- На `5xx` — экспоненциальная задержка.
- На `404` — `FaceitNotFound`.
- На остальные `4xx` — `FaceitError` без ретрая.
- Таймауты и сетевые ошибки сразу превращаются в `FaceitError`.
- Некорректный JSON или неожиданная схема — `FaceitError`.

#### Кэширование

- Встроенный `_TTLCache` с TTL 300 секунд.
- Ключ включает имя метода и аргументы.
- Кэшируются успешные ответы.
- `404` не кэшируется.
- `clear_cache()` полностью очищает кэш — используется кнопкой «Обновить».
- Кэш живёт в памяти процесса и не разделяется между инстансами.

#### Ошибки

- `FaceitError` — базовая ошибка.
- `FaceitNotFound` — 404.
- `FaceitRateLimit` — 429 после исчерпания ретраев; хранит `retry_after`.

### 7.5. `bot/steam.py`

Модуль отвечает за Steam-ссылки и дополнительную статистику.

#### Разбор ввода

`parse_steam_input()` поддерживает:

- `http(s)://steamcommunity.com/profiles/<7656119...>`;
- `http(s)://steamcommunity.com/id/<vanity>`;
- голый SteamID64;
- голое vanity-имя.

Правила:

- SteamID64 — 17 цифр, начинается с `7656119`.
- Vanity — 2–32 символа `[A-Za-z0-9_-]`.
- Числовая строка, не являющаяся SteamID64, отклоняется без запроса в Steam.
- Для прямых ссылок и голого SteamID64 сетевой запрос не нужен.
- Для vanity используется `ISteamUser/ResolveVanityURL` с `url_type=1`.
- Ответ проверяется: `success == 1`, `steamid` соответствует формату SteamID64.

#### Steam-статистика

`fetch_steam_stats()` загружает два ответа параллельно:

- `IPlayerService/GetOwnedGames` с `appid=730` (CS2);
- `ISteamUser/GetPlayerBans`.

Из них извлекается:

- часы CS2: `playtime_forever / 60`;
- `VACBanned`;
- `NumberOfVACBans`;
- `DaysSinceLastBan`.

Поведение:

- Если `STEAM_API_KEY` не задан — `None`.
- Если профиль закрыт или API недоступен — `None`.
- Если список игр получен, но CS2 в нём нет — `0.0` часов.
- Если нет ни часов, ни VAC-статуса — `None`.
- Ошибки не пробрасываются и не ломают основной ответ.
- Таймаут — 10 секунд.
- Для Steam создаётся отдельный `httpx.AsyncClient` на каждый вызов.

### 7.6. `bot/stats.py`

Самый большой модуль: модели и вся бизнес-логика расчётов.

#### Основные модели

- `PlayerProfile` — ник, страна, аватар, Faceit URL, регион, ELO, уровень, максимальный ELO.
- `PlayerRanking` — позиции страны и региона.
- `LifetimeSummary` — матчи, винрейт, K/D, HS%, лучшая серия, текущая серия.
- `RecentForm` — средние за последние матчи и последовательность результатов.
- `MapPerformance` — карта, винрейт, число матчей.
- `MatchSummary` — карта, счёт, K/D/A, изменение ELO, результат.
- `PlayerStats` — полный набор данных для форматирования.

#### Lifetime-статистика

Берутся только средние поля:

- K/D — **`Average K/D Ratio`**;
- HS% — **`Average Headshots %`**.

Накопительные `K/D Ratio` и `Total Headshots %` игнорируются, даже если присутствуют в ответе.

Дополнительно:

- Матчи: `Matches`, `Total Matches`, `Total Matches Played`.
- Победы: `Wins`, `Total Wins`.
- Винрейт: `Win Rate %`, `Win Rate`; если нет — считается как `wins / matches * 100`.
- Лучшая серия: `Longest Win Streak`, `Best Win Streak`.
- Текущая серия побед: `Current Win Streak`, `Current Winning Streak`.

Санити-проверки:

- винрейт должен быть в диапазоне `0–100`, иначе строка пропускается;
- K/D должен быть в диапазоне `0–10`, иначе пропускается и пишется warning с сырым значением;
- HS% должен быть в диапазоне `0–100`, иначе пропускается и пишется warning с сырым значением.

Поиск ключей не зависит от регистра и лишних пробелов.

#### Форма за последние матчи

- Берётся до 20 матчей.
- Считаются:
  - средний K/D (из `K/D Ratio` или `Kills / Deaths`);
  - средний ADR (`ADR`, `Average Damage per Round`);
  - средний K/R (`K/R Ratio`, `K/R`);
  - средние килы;
  - винрейт по распознанным результатам.
- `results` хранится **от нового матча к старому**.
- `latest_ten` — первые 10 результатов.
- `previous_ten` — следующие 10, но в сообщении **не выводится**.
- `analyzed_matches` — сколько матчей реально попало в окно анализа.

#### Текущая серия

Логика:

1. Если есть результаты последних матчей, серия считается по ним.
2. Если серия победная — берётся максимум из серии по последним матчам и lifetime `Current Win Streak`. Это нужно, потому что lifetime-серия может быть длиннее окна в 20 матчей.
3. Если серия проигрышная — она имеет приоритет над lifetime-победной серией.
4. Если результатов нет — используется lifetime `Current Win Streak`.
5. Если данных нет вообще — строка не выводится.

#### Карты

Источник — `segments` из lifetime-статистики.

- Учитываются сегменты с `type == "map"` или label, начинающимся с `de_`.
- Дубликаты по имени отбрасываются.
- Нужно минимум 1 матч.
- Винрейт берётся из `Win Rate %` или считается из `Wins / Matches`.
- Все карты сохраняются в `PlayerStats.maps` и сортируются по:
  1. винрейту по убыванию;
  2. числу матчей по убыванию;
  3. имени.

Классификация:

- **лучшая** — минимум 30 матчей и винрейт **выше** общего lifetime-винрейта;
- **слабая** — минимум 30 матчей и винрейт **ниже** общего;
- **нейтральная** — 30+ матчей и винрейт равен общему;
- **мало данных** — меньше 30 матчей, всегда `⚠️`, даже если винрейт высокий.

Тай-брейк для лучших/слабых — число матчей. Если общего винрейта нет, `best_maps` и `weak_maps` не строятся.

#### Рейтинг

`build_player_ranking()` собирает позиции страны и региона.

- Позиция должна быть `>= 1`.
- Если позиций нет — `None`.
- Позиции используются только как признак наличия данных.
- В сообщении выводятся только страна и регион, **без `#позиций`**:
  - `• Страна: 🇰🇿 KZ`
  - `• Регион: EU`

#### Последние 5 матчей

`_build_last_matches()`:

- Берёт до 6 последних матчей, чтобы посчитать ±ELO для пятого.
- Для каждого матча:
  - карта — из `stats["Map"]`;
  - счёт — из деталей `/matches/{match_id}`;
  - K/D/A — из статистики матча;
  - изменение ELO — явное поле или разница с предыдущим матчем;
  - результат — win/loss.
- Если у матча нет полезных данных, строка пропускается.

Счёт ориентируется **с точки зрения игрока**:

- если в составах удалось найти фракцию игрока — сначала его счёт;
- если составов нет:
  - победа → `max:min`;
  - поражение → `min:max`;
  - неизвестный результат → порядок из ответа API.

ELO:

- приоритет у явных `elo_delta`, `elo_change`, `Elo Delta`, `Elo Change`, `ELO Change`;
- иначе считается как `текущий ELO - ELO следующего (более старого) матча`;
- для пятого матча нужен шестой — поэтому `RECENT_MATCHES_FETCH_LIMIT = 21`.

#### Faceit URL

`PlayerProfile.profile_url`:

- если `faceit_url` начинается с `http://` или `https://`, он используется;
- `{lang}` и `%7Blang%7D` заменяются на `en` без учёта регистра;
- иначе строится fallback:
  `https://www.faceit.com/en/players/<urlencoded nickname>`.

#### Максимальный ELO

Ищется в CS2-профиле и в корне ответа по полям:

- `max_faceit_elo`
- `max_elo`
- `highest_elo`
- `faceit_elo_max`
- `max elo`

Официальный Faceit Data API обычно не отдаёт максимальный ELO, поэтому блок часто отсутствует.

### 7.7. `bot/formatter.py`

Отвечает только за представление. Вход — `PlayerStats`, выход — Telegram HTML и клавиатура.

#### Порядок блоков

1. Шапка:
   - `🎮 <b><a href="...">Ник</a></b> 🇰🇿`
   - `🏅 Уровень 10 · 2345 ELO`
   - `📈 Максимальный ELO: 2600`
2. `🌍 Рейтинг`
3. `📊 Общая статистика`
4. `🔥 Форма за последние 20 матчей`
5. `🕹️ Последние 5 матчей`
6. `🗺️ Карты`
7. `💻 Steam`
8. `Обновлено HH:MM`

#### Общая статистика

Выводится:

- `• Матчей: N`
- `• Винрейт: 55% (20 матчей: 60% ↑)`
- `• K/D: 1.25 (20 матчей: 1.30 ↑)`
- `• HS%: 48%`
- `• Лучшая серия побед: 10`
- `• Текущая серия: 2 победы` / `3 поражения`

Тренды:

- сравнивается lifetime-значение со средним за последние матчи;
- `↑` — recent выше;
- `↓` — recent ниже;
- при равенстве стрелки нет;
- если одного из значений нет, суффикс не выводится.

Нюанс: подпись всегда говорит `20 матчей`, даже если реально проанализировано меньше.

#### Форма

- `• Средний K/D: 1.30`
- `• Средний ADR: 77.4`
- `• Средний K/R: 0.87`
- `• Средние килы: 20.5`
- `• Винрейт: 60%`
- `• Результаты последних 10 матчей: ✅❌✅❌...`

Результаты идут **от нового к старому**. Строка `Предыдущие 10` не выводится.

#### Последние 5 матчей

Формат:

```text
• de_mirage · 13:9 · 25/12/5 · +20 ELO
• de_dust2 · 7:13 · 15/20/3 · −18 ELO
```

Недостающие части опускаются. Отрицательное ELO форматируется с символом `−`.

#### Карты

Одна таблица всех карт:

```text
🗺️ Карты
🏆 de_mirage — 75% · 40 матчей
▫️ de_dust2 — 55% · 30 матчей
📉 de_inferno — 30% · 31 матч
⚠️ de_overpass — 90% · 12 матчей
<i>🏆 лучшие · 📉 слабые · ⚠️ меньше 30 матчей</i>
```

Маркеры:

- `🏆` — лучшая карта;
- `📉` — слабая карта;
- `⚠️` — меньше 30 матчей;
- `▫️` — нейтральная карта.

Символ `•` в таблице карт больше не используется. Легенда выводится только для присутствующих категорий.

#### Steam

```text
💻 Steam
• CS2: 1234.5 ч
• VAC: ✅ нет
```

При бане:

```text
• VAC: ⛔ бан (2 бана, 30 дн. назад)
```

Часы форматируются как целое число, если значение близко к целому, иначе с одним знаком после запятой.

#### Экранирование и лимит

- Ник, названия карт и URL экранируются для HTML.
- Ник обрезается до 64 символов, название карты — до 48, URL — до 512.
- Итоговый текст ограничен **4096 символами**.
- При превышении бот обрезает текст по последнему переводу строки и добавляет:
  `<i>Сообщение сокращено.</i>`
- Предполагается, что каждая строка содержит сбалансированные HTML-теги.

#### Клавиатура

```text
[ Открыть профиль на Faceit ]
[ Обновить ]
```

Callback-data: `refresh:<SteamID64>`.

## 9. Устойчивость и обработка ошибок

Проект спроектирован так, чтобы одна недоступная часть API не ломала весь ответ.

### Обязательные данные

- Профиль игрока.
- Хотя бы один из двух источников: lifetime или recent matches.

Если оба источника упали — пользователь получает сообщение об ошибке.

### Необязательные данные

- Рейтинг страны/региона.
- Steam-статистика.
- Детали конкретных матчей.
- Максимальный ELO.

Их ошибки:

- логируются;
- не пробрасываются;
- соответствующий блок просто не выводится.

### Прочее

- 404 при поиске игрока → «нет Faceit-аккаунта с CS2».
- 404 при рейтинге или деталях матча → `None`.
- 429 после ретраев → отдельное сообщение о лимите.
- Сетевые ошибки Faceit → общее сообщение об ошибке.
- Неожиданные исключения в хендлере → `logger.exception` и безопасный ответ пользователю.
- Детали матчей загружаются параллельно; ошибка одного матча не мешает остальным.

## 11. Текущие ограничения и нюансы

1. **Нет базы данных.** История матчей, графики прогресса и сравнение игроков потребуют отдельного хранилища.
2. **Кэш только в памяти.** После рестарта он пуст; несколько инстансов бота не разделяют кэш.
3. **Нет rate limiting для пользователей.** Один человек может многократно дергать бота и расходовать лимиты Faceit.
4. **Нет фоновой очереди.** Тяжёлые запросы выполняются прямо в обработчике.
5. **Только long polling.** Webhook, Docker, CI и деплой-конфиги отсутствуют.
6. **Только CS2.** Другие игры Faceit не поддерживаются.
7. **Голый SteamID64/vanity в чате не обрабатывается.** `resolve_steam_id` их понимает, но `handle_link` сначала требует `http(s)`-ссылку.
8. **Подпись тренда всегда «20 матчей».** Даже если реально загружено меньше матчей.
9. **Последовательность результатов может быть короче 10.** Если API не отдал `Result` для части матчей, а подпись остаётся «последних 10».
10. **Максимальный ELO часто недоступен.** Официальный Faceit Data API обычно не отдаёт это поле, поэтому блок часто пропускается.
11. **Время внизу — локальное время сервера.** Часовой пояс пользователя не учитывается.
12. **Обрезка сообщения по переводу строки.** В редком случае одной очень длинной строки теоретически можно разорвать HTML-разметку.
13. **Steam-статистика требует публичного профиля и ключа.** При закрытом профиле блок просто исчезает.
14. **Нет локализации.** Все тексты на русском, i18n не предусмотрен.

## 12. Возможные направления развития

1. **История и графики.** Сохранять матчи в SQLite/PostgreSQL и строить динамику ELO, K/D и винрейта.
2. **Сравнение двух игроков.** Новый сценарий с двумя ссылками и сводной таблицей.
3. **Кэш в БД.** Переживать рестарты и разделять данные между инстансами.
4. **Rate limiting и очередь.** Защита от спама и более равномерная нагрузка на Faceit API.
5. **Webhook + Docker + CI.** Production-развёртывание и автоматические проверки.
6. **Настройка часового пояса и языка.** Пользовательские preferences.
7. **Больше Steam-данных.** Например, время за последние две недели, количество игр, другие баны.
8. **Аналитика по последним матчам.** Винрейт и K/D не за всю жизнь, а за последние 20/50 матчей.
9. **Поддержка других игр Faceit.** Не только CS2.
10. **Исправление ввода без URL.** Пробовать `parse_steam_input` на всём тексте сообщения, если URL не найден.
11. **Более точные подписи трендов.** Писать фактическое число проанализированных матчей вместо статического «20 матчей».
12. **Кнопка «Обновить» с индикатором загрузки.** Сейчас есть только `typing`-action и всплывающий ответ callback.

## 13. Итог

Это аккуратно разделённый на слои, полностью асинхронный Telegram-бот с:

- надёжным клиентом Faceit API с ретраями и TTL-кэшем;
- отдельным Steam-модулем;
- продуманной бизнес-логикой расчётов;
- устойчивым форматированием HTML с экранированием и лимитом Telegram;
- хорошим покрытием тестами без реальных сетевых запросов.

Основной сценарий полностью рабочий: ссылка → SteamID64 → Faceit-профиль → статистика CS2 → HTML-сообщение с картами, формой, последними матчами, рейтингом и Steam-блоком.

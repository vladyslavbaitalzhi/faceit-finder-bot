# Faceit Finder Bot — полное описание проекта

## 1. Что это за проект

**Faceit Finder Bot** — Telegram-бот на Python, который по ссылке на Steam-профиль находит игрока на Faceit и присылает подробную статистику по CS2.

Основной сценарий:

1. Пользователь отправляет боту ссылку на Steam-профиль.
2. Бот извлекает SteamID64.
3. Через Faceit Data API v4 находит Faceit-аккаунт, привязанный к этому SteamID64.
4. Параллельно загружает lifetime-статистику, последние матчи, рейтинги, детали матчей и данные Steam.
5. Считает производные показатели: винрейт, K/D, форму, серии, карты, изменения ELO.
6. Формирует HTML-сообщение для Telegram и inline-клавиатуру.

Дополнительный сценарий — **сравнение двух игроков**:

1. Пользователь запускает сравнение одним из способов: «⚔️ Сравнить игроков» (два шага), «⚔️ Сравнить с другим игроком» под профилем (сразу второй шаг), `/compare <url1> <url2>` или просто две ссылки одним сообщением.
2. Бот параллельно резолвит оба SteamID64 и параллельно загружает статистику обоих игроков.
3. Считает разницу по ELO, винрейту, K/D, HS%, ADR, текущей серии и часам CS2.
4. Формирует компактную таблицу, где лучший показатель каждой метрики выделен жирным шрифтом и 🏆.
5. Под сообщением показывает кнопки профилей обоих игроков и «Обновить сравнение».

Для навигации используется постоянное Reply-меню внизу чата и inline-кнопки на стартовом экране; пошаговое сравнение работает на лёгком FSM aiogram.

Проект не хранит данные в базе: он работает как stateless-сервис с in-memory кэшем ответов Faceit API.

## 4. Конфигурация и запуск

### Переменные окружения

Файл `.env` читается через `pydantic-settings`:

| Переменная | Обязательна | Что делает |
|---|---|---|
| `BOT_TOKEN` | Да | Токен Telegram-бота от @BotFather |
| `STEAM_API_KEY` | Нет | Нужен для vanity-ссылок `/id/...`, часов CS2 и VAC-статуса |
| `FACEIT_API_KEY` | Нет | Нужен для запросов статистики Faceit |
| `RATE_LIMIT_REQUESTS` | Нет | Лимит единиц действий пользователя за окно (по умолчанию 10) |
| `RATE_LIMIT_WINDOW_SECONDS` | Нет | Длина окна лимита в секундах (по умолчанию 60) |
| `RATE_LIMIT_HEAVY_WEIGHT` | Нет | Вес сравнения и refresh (по умолчанию 2) |
| `FACEIT_MAX_CONCURRENCY` | Нет | Максимум одновременных запросов к Faceit (по умолчанию 5) |
| `FACEIT_MAX_REQUESTS_PER_SECOND` | Нет | Проактивный лимит исходящих запросов Faceit в секунду, token bucket (по умолчанию 4) |
| `FACEIT_RATE_LIMIT_COOLDOWN_SECONDS` | Нет | Минимальная глобальная пауза после 429 (по умолчанию 30) |
| `FACEIT_RATE_LIMIT_COOLDOWN_MAX_SECONDS` | Нет | Потолок глобальной паузы после 429 (по умолчанию 300) |
| `FACEIT_CACHE_MAX_ENTRIES` | Нет | Максимум записей TTL/LRU-кэша Faceit (по умолчанию 2500) |
| `FACEIT_NEGATIVE_CACHE_TTL_SECONDS` | Нет | Сколько секунд помнить 404 по поиску игрока (по умолчанию 60) |
| `REFRESH_COOLDOWN_SECONDS` | Нет | Минимальный интервал refresh одного игрока (по умолчанию 60) |

Особенности:

- Без `BOT_TOKEN` приложение не запустится.
- Без `STEAM_API_KEY`:
  - прямые ссылки `/profiles/<SteamID64>` работают;
  - короткие ссылки `/id/<vanity>` не разрешаются;
  - блок Steam не выводится.
- Без `FACEIT_API_KEY` бот запускается, но на любую ссылку отвечает:
  `Проверка Faceit не настроена: добавь FACEIT_API_KEY в .env.`
- Секреты хранятся в `SecretStr`, `.env` исключён через `.gitignore`.

## 5. Пользовательский сценарий

### Команды

- `/start` — приветствие с inline-кнопками быстрого доступа и постоянным Reply-меню.
- `/help` — справка по использованию.
- `/compare <url1> <url2>` — быстрое сравнение двух игроков Faceit.
- `/cancel` — отменить пошаговый ввод и вернуться в меню.

### Меню и навигация

Постоянное `ReplyKeyboardMarkup` внизу чата содержит:

- «🔍 Найти игрока»;
- «⚔️ Сравнить игроков»;
- «ℹ️ Помощь».

`/start` отправляет:

1. Приветствие с inline-клавиатурой `build_start_keyboard()`: быстрый поиск, сравнение и помощь.
2. Короткое сообщение с `build_main_menu_keyboard()` — постоянное Reply-меню.

Меню не отменяет старые способы ввода: одну ссылку можно отправить сразу после приветствия, а две ссылки — без нажатия кнопок.

### Сравнение двух игроков

Поддерживаются четыре способа сравнения:

1. Быстрый старт из профиля — кнопка «⚔️ Сравнить с другим игроком» под одиночным сообщением:
   - SteamID64 текущего игрока сохраняется в `compare_left_steam64`;
   - FSM сразу переводится в `CompareFlow.waiting_second`;
   - бот присылает новое сообщение с просьбой отправить ссылку на второго игрока;
   - ник первого берётся только из кэша профиля, без HTTP-запросов;
   - повторное нажатие при том же первом игроке не дублирует сообщение.
2. Пошаговый сценарий из меню «⚔️ Сравнить игроков»:
   - бот переводит FSM в `CompareFlow.waiting_first` и просит первого игрока;
   - после успешного резолвинга и проверки Faceit-профиля переходит в `CompareFlow.waiting_second`;
   - после второй ссылки показывает сравнение;
   - на каждом шаге доступна inline-кнопка «Отмена» и команда `/cancel`.
3. Команда:
   ```text
   /compare <url1> <url2>
   ```
4. Обычное сообщение, в котором ровно две `http(s)`-ссылки. Разделители `vs`, `и`, `and`, `&`, `против` и запятые игнорируются.

В `/compare` и пошаговом сценарии дополнительно принимаются голые SteamID64 и vanity-имена, потому что ввод разбирается тем же `parse_steam_input()`.

Если на первом шаге сразу отправить две ссылки, бот пропускает второй шаг и сравнивает немедленно.

FSM использует встроенный `MemoryStorage` aiogram: состояние живёт в памяти процесса, не требует БД и сбрасывается при рестарте. При нажатии `/start`, `/help`, `/compare`, кнопок меню или «Отмена» состояние очищается.

Валидация:

1. `_parse_compare_inputs()` извлекает ссылки; если их меньше двух, разбирает токены и оставляет те, которые понимает `parse_steam_input()`.
2. `_resolve_compare_inputs()` параллельно резолвит оба значения в SteamID64 через `asyncio.gather`.
3. Если хотя бы один SteamID64 получить не удалось — выводится общее сообщение о невалидной ссылке.
4. Совпадающие SteamID64 отклоняются до загрузки.
5. Совпадающие Faceit `player_id` отклоняются после загрузки — на случай разных Steam-аккаунтов, привязанных к одному Faceit-профилю.

Загрузка:

- Внешний `asyncio.gather(..., return_exceptions=True)` запускает два независимых `_load_player_stats()`.
- Внутри каждого плеча уже работает свой `gather` для lifetime, recent matches, Steam и рейтингов.
- Ошибка или отсутствие игрока с одной стороны не мешает загрузке второй.
- `FaceitRateLimit` показывается отдельным сообщением.
- Если не найден только первый или только второй игрок, бот явно говорит, какой именно.
- Если оба игрока не найдены — отдельное сообщение; если оба упали с другими ошибками — общее сообщение об ошибке.

Сравнение и обновление:

- `build_player_comparison()` считает метрики и победителя по каждой.
- `format_player_comparison()` формирует HTML.
- `build_comparison_keyboard()` добавляет две кнопки профилей и «Обновить сравнение».
- Callback обновления: `refresh_compare:<SteamID64_left>:<SteamID64_right>`.
- При первичном показе сравнения время загрузки фиксируется для обоих игроков.
- При обновлении кэш обоих игроков инвалидируется точечно (только их записи), оба игрока загружаются заново, сообщение редактируется через `edit_text` с fallback на новое сообщение.
- Cooldown сравнения проверяется по каждому SteamID64 отдельно: если хотя бы один участник обновлялся менее `REFRESH_COOLDOWN_SECONDS` назад, callback отвечает «Данные уже свежие, обновлены X сек назад» без запросов к Faceit. Перестановка A/B или замена второго игрока не обходит cooldown.

### Обработка ссылки

Бот реагирует на текстовые сообщения, в которых есть `http(s)`-ссылка.

Поддерживаются:

- `https://steamcommunity.com/profiles/<SteamID64>`;
- `https://steamcommunity.com/id/<vanity>`;
- ссылки с `http`, `www`, завершающим слэшем, query-параметрами и якорем.

Дополнительно `parse_steam_input()` умеет разбирать:

- голый SteamID64;
- голое vanity-имя;
- отклоняет числовые строки, не похожие на SteamID64, чтобы не делать лишний запрос в Steam.

Важный нюанс текущей реализации: в чате `handle_link()` сначала ищет именно URL. Поэтому голый SteamID64 или vanity-имя без ссылки до резолвера не дойдут — бот ответит «Не вижу ссылки». Резолвер их поддерживает, но обработчик сообщения требует URL.

### Ответы на ошибки

- Нет ссылки → `Не вижу ссылки в сообщении. 🤔`
- Не удалось получить SteamID64 → `Не удалось получить SteamID64 по этой ссылке. 🤔`
- Нет Faceit-аккаунта с CS2 → `У этого игрока нет Faceit-аккаунта с CS2`
- Нет `FACEIT_API_KEY` → сообщение о ненастроенной проверке.
- Faceit вернул 429 → `Faceit временно ограничил количество запросов. Попробуй чуть позже.`
- Другая ошибка Faceit → `Не удалось получить статистику Faceit. Попробуй ещё раз позже.`

Для сравнения:

- `/compare` без аргументов → краткая инструкция;
- одна ссылка → просьба прислать вторую;
- больше двух ссылок → просьба оставить две;
- невалидный SteamID64 хотя бы у одной ссылки → `Не удалось получить SteamID64 для одной из ссылок. 🤔`;
- одинаковые игроки → `Нельзя сравнивать игрока с самим собой.`;
- не найден первый или второй игрок → отдельные сообщения с указанием стороны;
- 429 → общее сообщение про лимит Faceit;
- нет ни одной общей метрики → `Недостаточно данных для сравнения игроков.`

Для пошагового сравнения дополнительно:

- пустой ввод или текст без ссылки → просьба прислать ссылку;
- на первом шаге можно отправить сразу две ссылки;
- на втором шаге требуется ровно одна ссылка;
- повторный ввод того же игрока → `Нельзя сравнивать игрока с самим собой.`;
- истёкшие данные FSM → `Сессия сравнения устарела. Начни сравнение заново.`;
- «Отмена», `/cancel` или callback `menu:cancel` → сброс состояния и экран отмены.

### Inline-кнопки

На стартовом экране:

- «🔍 Найти игрока» — callback `menu:find`;
- «⚔️ Сравнить игроков» — callback `menu:compare`;
- «ℹ️ Помощь» — callback `menu:help`.

На экранах меню и помощи:

- «Отмена» — callback `menu:cancel`;
- «⬅️ В главное меню» — callback `menu:main`.

Под одиночным сообщением:

- **«Открыть профиль на Faceit»** — ссылка на профиль;
- **«Обновить»** — callback `refresh:<SteamID64>`;
- **«⚔️ Сравнить с другим игроком»** — callback `compare_with:<SteamID64>`: запоминает игрока первым, сразу ставит `CompareFlow.waiting_second` и присылает новое сообщение с подсказкой и кнопкой «Отмена». Статистика не редактируется, HTTP-запросов нет; ник для подсказки берётся из кэша профиля (`peek_player_nickname`).

Под сообщением сравнения:

- **«1. &lt;ник&gt;»** и **«2. &lt;ник&gt;»** — ссылки на профили;
- **«🔄 Обновить сравнение»** — callback `refresh_compare:<SteamID64_left>:<SteamID64_right>`.

При обновлении одиночного сообщения:

1. Проверяется корректность SteamID64 и cooldown цели.
2. Если данные обновлялись меньше `REFRESH_COOLDOWN_SECONDS` назад, callback отвечает «Данные уже свежие, обновлены X сек назад» и сеть не используется.
3. Иначе cooldown цели резервируется сразу после проверки, до первого `await`: параллельный refresh той же цели увидит отметку и не запустит вторую загрузку.
4. Из кэша удаляются только записи этого игрока.
5. Статистика загружается заново.
6. При `FaceitError` или другом исключении резерв снимается через `RefreshCooldown.release()`, поэтому после ошибки refresh снова доступен. При успехе отметка остаётся.
7. Сообщение редактируется через `edit_text`.
8. Если Telegram отвечает `message is not modified`, ошибка игнорируется.
9. При другой ошибке редактирования бот отправляет новое сообщение.

Время последней загрузки записывается и при первичном успешном показе профиля (и сравнения), а не только при refresh. Поэтому нажатие «Обновить» сразу после показа отвечает, что данные уже свежие, и не тратит квоту Faceit.

## 6. Архитектура и поток данных

```text
Telegram Update
      │
      ├── /start, /help, Reply-меню, inline-меню
      │         │
      │         ├── build_start_keyboard()
      │         ├── build_main_menu_keyboard()
      │         ├── build_help_keyboard()
      │         └── state.clear()
      │
      ├── «⚔️ Сравнить игроков» / menu:compare
      │         │
      │         ├── CompareFlow.waiting_first
      │         │       ├── две ссылки → _handle_compare_request()
      │         │       └── одна ссылка → resolve + get_player_by_steam_id()
      │         │               └── CompareFlow.waiting_second
      │         │
      │         ├── CompareFlow.waiting_second
      │         │       └── _send_comparison_result()
      │         │
      │         └── menu:cancel / /cancel → state.clear()
      │
      ├── «⚔️ Сравнить с другим игроком» / compare_with:
      │         │
      │         ├── peek_player_nickname()      # только кэш, без HTTP
      │         └── CompareFlow.waiting_second
      │                 compare_left_steam64 = <SteamID64 из кнопки>
      │
      ├── /compare → handlers.handle_compare()
      │         │
      │         ├── _parse_compare_inputs()
      │         ├── _resolve_compare_inputs()
      │         │       └── asyncio.gather(resolve_steam_id(), resolve_steam_id())
      │         │
      │         └── _build_comparison_message()
      │                 │
      │                 ├── _load_comparison_stats()
      │                 │       └── asyncio.gather(
      │                 │             _load_player_stats(left),
      │                 │             _load_player_stats(right),
      │                 │           )
      │                 │
      │                 ├── build_player_comparison()
      │                 └── format_player_comparison()
      │                     build_comparison_keyboard()
      │
      ▼
handlers.handle_link()
      │
      ├── _extract_urls()                # ссылки из текста
      │
      ├── 2 ссылки → _handle_compare_request()
      │
      ├── resolve_steam_id()             # SteamID64
      │       └── Steam Web API          # только для vanity
      │
      └── _load_player_stats()
              │
              ├── Faceit: GET /players?game=cs2&game_player_id=...
              │
              ├── asyncio.gather(...)
              │       ├── lifetime stats
              │       ├── recent matches (limit=21)
              │       ├── Steam stats
              │       ├── region ranking
              │       └── country ranking
              │
              ├── _load_match_details()  # детали первых 5 матчей
              │
              └── build_player_stats()
                      │
                      ▼
              format_player_stats()
              build_player_keyboard()
                      │
                      ▼
              message.answer() / edit_text()
```

Все независимые запросы выполняются параллельно через `asyncio.gather(..., return_exceptions=True)`. Это позволяет показывать частичную статистику, если, например, рейтинг или Steam недоступны. В сравнении внешний `gather` изолирует сбои каждой стороны: ошибка загрузки одного игрока не отменяет загрузку второго.

FSM для пошагового сравнения использует `MemoryStorage` aiogram. Состояние не сохраняется в БД и теряется при рестарте; это осознанный компромисс ради интерактивного UX без внешнего хранилища.

## 7. Подробно по модулям

### 7.1. `config.py`

Содержит `Settings` на базе `BaseSettings`.

- `.env` ищется рядом с `config.py`.
- Пустые переменные игнорируются.
- Неизвестные переменные игнорируются.
- `bot_token` — обязательный `SecretStr`.
- `steam_api_key`, `faceit_api_key` — необязательные `SecretStr`.
- Глобальный объект `settings` создаётся при импорте.

### 7.2. `bot/main.py`

Отвечает за запуск приложения.

- Настраивает логирование.
- Предупреждает, если не заданы Steam/Faceit ключи.
- Создаёт `FaceitClient` только при наличии `FACEIT_API_KEY`.
- Создаёт `Bot` с `ParseMode.HTML` по умолчанию.
- Создаёт `Dispatcher`, подключает `router`, кладёт `faceit_client` и `refresh_cooldown` в DI-контейнер.
- Регистрирует `RateLimitMiddleware` как outer middleware для `Message` и `CallbackQuery`.
- Использует встроенный `MemoryStorage` aiogram (создаётся диспетчером по умолчанию) для FSM пошагового сравнения.
- Удаляет webhook с `drop_pending_updates=True`.
- Запускает long polling.
- В `finally` закрывает сессию бота и HTTP-клиент Faceit.

### 7.3. `bot/handlers.py`

Главный сценарийный модуль.

Ключевые функции:

- `_extract_urls()` — находит все ссылки и обрезает хвостовую пунктуацию.
- `_parse_compare_inputs()` — разбирает аргументы `/compare` в два Steam-идентификатора.
- `_resolve_compare_inputs()` — параллельно резолвит оба входа в SteamID64.
- `_unwrap_stats_response()` — разбирает результаты `gather` для обязательных запросов.
- `_optional_payload()` — безопасно обрабатывает необязательные ответы.
- `_load_match_details()` — загружает детали первых пяти матчей по `match_id`.
- `_load_player_stats()` — основной оркестратор загрузки одного игрока.
- `_load_comparison_stats()` — внешний `gather` двух `_load_player_stats()`.
- `_build_comparison_message()` — загружает обоих и собирает текст и клавиатуру сравнения.
- `_handle_compare_request()` — валидирует ввод и отправляет сравнение.
- `_start_compare_flow()` / `_cancel_compare_flow()` — запуск и сброс пошагового сравнения.
- `_handle_compare_first_input()` / `_handle_compare_second_input()` — шаги FSM-сценария.
- `_send_comparison_result()` — отправляет готовое сравнение с обработкой ошибок.
- `_refresh_is_allowed()` — проверяет cooldown refresh и всегда отвечает на callback.
- `_edit_inline_or_answer()` — редактирует inline-экран с fallback на новое сообщение.
- `_build_message()` — собирает текст и клавиатуру одиночного профиля.
- `handle_start()`, `handle_help()`, `handle_cancel()`, `handle_compare()`, `handle_link()`, `handle_compare_with()`, `handle_refresh()`, `handle_compare_refresh()`.
- `handle_menu_find_text()`, `handle_menu_compare_text()`, `handle_menu_help_text()` — Reply-кнопки.
- `handle_menu_find()`, `handle_menu_compare()`, `handle_menu_help()`, `handle_menu_cancel()`, `handle_menu_main()` — inline-callbacks.
- `handle_compare_first_step()`, `handle_compare_second_step()` — FSM-состояния.

Меню и FSM:

- `CompareFlow` содержит два состояния: `waiting_first` и `waiting_second`.
- В FSM хранится только `compare_left_steam64`. Ник первого игрока берётся из ответа Faceit на шаге 1 и сразу подставляется в подсказку шага 2; в данных состояния он не сохраняется.
- `handle_compare_with()` (callback `compare_with:<SteamID64>`) переиспользует `waiting_second`: записывает SteamID64 в `compare_left_steam64`, перезаписывает любое прежнее состояние и отправляет новое сообщение с подсказкой. Ник читается только из кэша через `peek_player_nickname()`; без кэша используется общая формулировка. Повторное нажатие при том же игроке только отвечает «Уже жду ссылку на второго игрока» без нового сообщения.
- `/start` очищает состояние, отправляет приветствие с `build_start_keyboard()` и отдельное сообщение с `build_main_menu_keyboard()`.
- `/help`, `/compare`, кнопки меню, «Отмена» и `/cancel` также очищают FSM.
- Если на первом шаге отправить две ссылки, сценарий сразу переходит к сравнению и очищает состояние.
- Порядок регистрации важен: обработчики меню и FSM-состояний объявлены до `handle_link()`, поэтому прямые ссылки и старые сценарии не перехватываются. Callback-хендлер `handle_compare_with()` объявлен до `handle_refresh()`, а префикс `compare_with:` не пересекается с `refresh:`, `refresh_compare:` и `menu:*`.

Логика `_load_player_stats()`:

1. `get_player_by_steam_id(steam64)`.
2. Если игрок не найден — `None`.
3. Из профиля достаются `player_id`, `region`, `country`.
4. Параллельно запускаются:
   - lifetime-статистика;
   - последние 21 матч;
   - Steam-статистика;
   - рейтинг региона, если известен регион;
   - рейтинг страны, если известны регион и страна.
5. Если и lifetime, и recent упали с ошибкой — ошибка пробрасывается.
6. Если упал только один из них — бот показывает то, что удалось загрузить.
7. Рейтинг и Steam считаются необязательными: их ошибки только логируются.
8. Загружаются детали первых пяти матчей.
9. Вызывается `build_player_stats()`.

Особенности:

- Перед загрузкой бот отправляет `typing`-action.
- Для обычного сообщения используется `answer(..., disable_web_page_preview=True)`.
- Для refresh — `edit_text`, с fallback на новое сообщение.
- Refresh инвалидирует только кэш целевого игрока и уважает `RefreshCooldown`.
- Если при refresh игрок исчез, сообщение заменяется на «нет Faceit-аккаунта», клавиатура убирается.

Логика сравнения:

1. `/compare` без аргументов отвечает инструкцией; одна или больше двух ссылок обрабатываются отдельными сообщениями до сети.
2. Оба Steam-идентификатора резолвятся параллельно.
3. Совпадающие SteamID64 отклоняются сразу, без запросов к Faceit.
4. `_load_comparison_stats()` запускает два `_load_player_stats()` через внешний `gather(return_exceptions=True)`.
5. Результат каждого плеча разбирается отдельно: `PlayerStats` либо исключение.
6. Если один игрок не найден, показывается сообщение именно про первую или вторую сторону.
7. `FaceitRateLimit` имеет приоритет над общим текстом ошибки.
8. После успешной загрузки сверяются Faceit `player_id`; совпадение отклоняется.
9. `build_player_comparison()` считает метрики; при отсутствии общих данных выводится отдельное сообщение.
10. Callback обновления содержит оба SteamID64, резервирует cooldown обоих игроков до загрузки, точечно инвалидирует их кэш и повторяет загрузку; при ошибке резерв снимается, а при активном cooldown сразу отвечает, что данные свежие.

### 7.4. `bot/faceit.py`

Асинхронный клиент Faceit Data API v4.

База:

```text
https://open.faceit.com/data/v4
```

Авторизация:

```text
Authorization: Bearer <FACEIT_API_KEY>
```

Используемые эндпоинты:

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `get_player_by_steam_id` | `GET /players?game=cs2&game_player_id=<steam64>` | Поиск игрока по SteamID64 |
| `get_lifetime_stats` | `GET /players/{player_id}/stats/cs2` | Lifetime-статистика и сегменты по картам |
| `get_recent_matches` | `GET /players/{player_id}/games/cs2/stats?limit=N` | Последние матчи |
| `get_player_ranking` | `GET /rankings/games/cs2/regions/{region}/players/{player_id}` | Позиция в рейтинге региона; опционально `country` |
| `get_match_details` | `GET /matches/{match_id}` | Счёт и составы матча |

Модели Pydantic:

- `FaceitGameProfile`
- `FaceitPlayer`
- `FaceitStatsSegment`
- `FaceitLifetimeStats`
- `FaceitMatch`
- `FaceitRecentMatches`
- `FaceitPlayerRanking`
- `FaceitMatchDetails`

Все модели используют `extra="ignore"`, то есть новые поля API не ломают парсинг.

#### Ретраи и поведение при 429

- По умолчанию `max_retries=3`, но это число действует только на ответы `5xx`.
- На `429` повторов нет. Клиент сразу продлевает глобальный cooldown:
  `max(Retry-After, FACEIT_RATE_LIMIT_COOLDOWN_SECONDS)`, но не больше
  `FACEIT_RATE_LIMIT_COOLDOWN_MAX_SECONDS` (300 с), и выбрасывает
  `FaceitRateLimit` с `retry_after`. Ветки `sleep + continue` для 429
  в коде отсутствуют.
- После получения слота семафора глобальный cooldown проверяется ещё раз:
  если за время ожидания другой запрос получил `429`, текущий запрос
  не идёт в сеть и сразу падает с `FaceitRateLimit`.
- Без `Retry-After` действует базовая пауза
  `FACEIT_RATE_LIMIT_COOLDOWN_SECONDS`.
- Кэшированные ответы проверяются до сетевой логики и обслуживаются даже
  при активном глобальном cooldown.
- Сообщение пользователю при известном `retry_after` дополняется фразой
  «Повтори примерно через N сек.» (округление вверх).
- На `5xx` — экспоненциальная задержка и повтор до исчерпания `max_retries`.
- На `404` — `FaceitNotFound`.
- На остальные `4xx` — `FaceitError` без ретрая.
- Таймауты и сетевые ошибки сразу превращаются в `FaceitError`.
- Некорректный JSON или неожиданная схема — `FaceitError`.

#### Параллелизм и single-flight

- Исходящие HTTP-запросы проходят token bucket со скоростью
  `FACEIT_MAX_REQUESTS_PER_SECOND` (по умолчанию 4 запроса/сек, всплеск
  не больше секунды). Токен берётся **до** семафора, поэтому ожидание
  пополнения не занимает слот параллелизма. Каждая повторная попытка
  после `5xx` тоже расходует токен; попадания в кэш — нет.
- Исходящие HTTP-запросы дополнительно ограничены `asyncio.Semaphore`
  (`FACEIT_MAX_CONCURRENCY`, по умолчанию 5).
- Одинаковые одновременные запросы с одним ключом `(path, params)`
  объединяются: один лидер выполняет HTTP, остальные ждут результат.
- Реальный запрос выполняется в отдельном `asyncio.Task` под
  `asyncio.shield`: отмена лидера или любого ожидающего не отменяет
  общий запрос для остальных.
- Кэш заполняется внутри задачи до её завершения, а запись in-flight
  удаляется done-callback после этого. Поэтому между «результат готов»
  и «запись удалена» нет окна, в котором повторный вызов ушёл бы в сеть.
- Ошибка лидера раздаётся всем ожидающим. Необработанное исключение
  задачи гасится в callback, поэтому нет предупреждений
  «Future exception was never retrieved».
- Отмена всех ожидающих не отменяет фоновый запрос: он доходит до конца
  и заполняет кэш для следующих вызовов.
- `aclose()` отменяет незавершённые single-flight задачи, дожидается их
  через `asyncio.gather(return_exceptions=True)`, очищает `_inflight`
  и только затем закрывает `httpx.AsyncClient`.

#### Кэширование

- Встроенный `_TTLCache` с TTL 300 секунд и максимумом
  `FACEIT_CACHE_MAX_ENTRIES` (2500) записей.
- Вытеснение — LRU, а не FIFO: обращения через `get()` переносят запись
  в конец `OrderedDict`. Просмотренные профили не вытесняются раньше
  действительно старых записей.
- Протухшие записи удаляются при обращении, раз в 100 операций записи
  (`purge_interval`) и перед вытеснением, поэтому они не накапливаются
  бесконечно и не вытесняют живые значения.
- Замеры репрезентативных ответов (рекурсивный `sys.getsizeof`):
  lifetime с 20 сегментами — ~15 КБ, recent matches на 21 матч — ~33 КБ,
  match details на 2 команды по 5 игроков — ~9 КБ, профиль — ~2 КБ,
  рейтинг на 50 записей — ~15 КБ.
- Оценка размера: один просмотр профиля создаёт до ~11 записей (~124 КБ),
  сравнение двух игроков — до ~22 записей (~249 КБ). Лимит 2500 записей
  покрывает ~227 просмотров или ~114 сравнений и занимает ~27 МБ;
  прежний лимит 6600 давал ~71 МБ.
- Ключ включает имя метода и аргументы.
- Кэшируются успешные ответы.
- `404` при поиске игрока кэшируется отдельно на
  `FACEIT_NEGATIVE_CACHE_TTL_SECONDS` (по умолчанию 60 с), чтобы повторные
  запросы по тому же SteamID64 не тратили квоту Faceit. Остальные `404`
  (рейтинг, детали матча) не кэшируются.
- Записи помечаются тегами `player:<player_id>` и `steam:<steam64>`.
  Steam-тег ставится и на lifetime/recent/рейтинги, поэтому «Обновить»
  удаляет данные игрока, даже если профиль уже протух или вытеснен из кэша.
- Детали завершённых матчей (`get_match_details`) игроками **не**
  тегируются: матч неизменяем, поэтому refresh профиля не сбрасывает их
  и не запрашивает повторно.
- `invalidate_player_by_steam_id()` удаляет и положительные, и негативные
  записи игрока; refresh сначала вызывает инвалидацию, поэтому негативный
  кэш не мешает повторной загрузке.
- `invalidate_player()` / `invalidate_player_by_steam_id()` выполняют
  точечную инвалидацию.
- `clear_cache()` оставлен как служебный метод и в пользовательских
  сценариях не используется.
- Кэш живёт в памяти процесса и не разделяется между инстансами.

#### Ошибки

- `FaceitError` — базовая ошибка.
- `FaceitNotFound` — 404.
- `FaceitRateLimit` — 429 (сразу, без ретраев) или активный глобальный cooldown; хранит `retry_after`.

### 7.5. `bot/steam.py`

Модуль отвечает за Steam-ссылки и дополнительную статистику.

#### Разбор ввода

`parse_steam_input()` поддерживает:

- `http(s)://steamcommunity.com/profiles/<7656119...>`;
- `http(s)://steamcommunity.com/id/<vanity>`;
- голый SteamID64;
- голое vanity-имя.

Правила:

- SteamID64 — 17 цифр, начинается с `7656119`.
- Vanity — 2–32 символа `[A-Za-z0-9_-]`.
- Числовая строка, не являющаяся SteamID64, отклоняется без запроса в Steam.
- Для прямых ссылок и голого SteamID64 сетевой запрос не нужен.
- Для vanity используется `ISteamUser/ResolveVanityURL` с `url_type=1`.
- Ответ проверяется: `success == 1`, `steamid` соответствует формату SteamID64.

#### Steam-статистика

`fetch_steam_stats()` загружает два ответа параллельно:

- `IPlayerService/GetOwnedGames` с `appid=730` (CS2);
- `ISteamUser/GetPlayerBans`.

Из них извлекается:

- часы CS2: `playtime_forever / 60`;
- `VACBanned`;
- `NumberOfVACBans`;
- `DaysSinceLastBan`.

Поведение:

- Если `STEAM_API_KEY` не задан — `None`.
- Если профиль закрыт или API недоступен — `None`.
- Если список игр получен, но CS2 в нём нет — `0.0` часов.
- Если нет ни часов, ни VAC-статуса — `None`.
- Ошибки не пробрасываются и не ломают основной ответ.
- Таймаут — 10 секунд.
- Для Steam создаётся отдельный `httpx.AsyncClient` на каждый вызов.

### 7.6. `bot/stats.py`

Самый большой модуль: модели и вся бизнес-логика расчётов.

#### Основные модели

- `PlayerProfile` — ник, страна, аватар, Faceit URL, регион, ELO, уровень, максимальный ELO.
- `PlayerRanking` — позиции страны и региона.
- `LifetimeSummary` — матчи, винрейт, K/D, HS%, лучшая серия, текущая серия.
- `RecentForm` — средние за последние матчи и последовательность результатов.
- `MapPerformance` — карта, винрейт, число матчей.
- `MatchSummary` — карта, счёт, K/D/A, изменение ELO, результат.
- `PlayerStats` — полный набор данных для форматирования.
- `ComparisonMetric` — Pydantic-модель одной строки сравнения: ключ, подпись, значения обоих игроков, `delta`, направление полезности и победитель.
- `PlayerComparison` — Pydantic-модель готового сравнения: два `PlayerStats` и кортеж метрик.

#### Lifetime-статистика

Берутся только средние поля:

- K/D — **`Average K/D Ratio`**;
- HS% — **`Average Headshots %`**.

Накопительные `K/D Ratio` и `Total Headshots %` игнорируются, даже если присутствуют в ответе.

Дополнительно:

- Матчи: `Matches`, `Total Matches`, `Total Matches Played`.
- Победы: `Wins`, `Total Wins`.
- Винрейт: `Win Rate %`, `Win Rate`; если нет — считается как `wins / matches * 100`.
- Лучшая серия: `Longest Win Streak`, `Best Win Streak`.
- Текущая серия побед: `Current Win Streak`, `Current Winning Streak`.

Санити-проверки:

- винрейт должен быть в диапазоне `0–100`, иначе строка пропускается;
- K/D должен быть в диапазоне `0–10`, иначе пропускается и пишется warning с сырым значением;
- HS% должен быть в диапазоне `0–100`, иначе пропускается и пишется warning с сырым значением.

Поиск ключей не зависит от регистра и лишних пробелов.

#### Форма за последние матчи

- Берётся до 20 матчей.
- Считаются:
  - средний K/D (из `K/D Ratio` или `Kills / Deaths`);
  - средний ADR (`ADR`, `Average Damage per Round`);
  - средний K/R (`K/R Ratio`, `K/R`);
  - средние килы;
  - винрейт по распознанным результатам.
- `results` хранится **от нового матча к старому**.
- `latest_ten` — первые 10 результатов.
- `previous_ten` — следующие 10, но в сообщении **не выводится**.
- `analyzed_matches` — сколько матчей реально попало в окно анализа.

#### Текущая серия

Логика:

1. Если есть результаты последних матчей, серия считается по ним.
2. Если серия победная — берётся максимум из серии по последним матчам и lifetime `Current Win Streak`. Это нужно, потому что lifetime-серия может быть длиннее окна в 20 матчей.
3. Если серия проигрышная — она имеет приоритет над lifetime-победной серией.
4. Если результатов нет — используется lifetime `Current Win Streak`.
5. Если данных нет вообще — строка не выводится.

#### Карты

Источник — `segments` из lifetime-статистики.

- Учитываются сегменты с `type == "map"` или label, начинающимся с `de_`.
- Дубликаты по имени отбрасываются.
- Нужно минимум 1 матч.
- Винрейт берётся из `Win Rate %` или считается из `Wins / Matches`.
- Все карты сохраняются в `PlayerStats.maps` и сортируются по:
  1. винрейту по убыванию;
  2. числу матчей по убыванию;
  3. имени.

Классификация:

- **лучшая** — минимум 30 матчей и винрейт **выше** общего lifetime-винрейта;
- **слабая** — минимум 30 матчей и винрейт **ниже** общего;
- **нейтральная** — 30+ матчей и винрейт равен общему;
- **мало данных** — меньше 30 матчей, всегда `⚠️`, даже если винрейт высокий.

Тай-брейк для лучших/слабых — число матчей. Если общего винрейта нет, `best_maps` и `weak_maps` не строятся.

#### Рейтинг

`build_player_ranking()` собирает позиции страны и региона.

- Позиция должна быть `>= 1`.
- Если позиций нет — `None`.
- Позиции используются только как признак наличия данных.
- В сообщении выводятся только страна и регион, **без `#позиций`**:
  - `• Страна: 🇰🇿 KZ`
  - `• Регион: EU`

#### Последние 5 матчей

`_build_last_matches()`:

- Берёт до 6 последних матчей, чтобы посчитать ±ELO для пятого.
- Для каждого матча:
  - карта — из `stats["Map"]`;
  - счёт — из деталей `/matches/{match_id}`;
  - K/D/A — из статистики матча;
  - изменение ELO — явное поле или разница с предыдущим матчем;
  - результат — win/loss.
- Если у матча нет полезных данных, строка пропускается.

Счёт ориентируется **с точки зрения игрока**:

- если в составах удалось найти фракцию игрока — сначала его счёт;
- если составов нет:
  - победа → `max:min`;
  - поражение → `min:max`;
  - неизвестный результат → порядок из ответа API.

ELO:

- приоритет у явных `elo_delta`, `elo_change`, `Elo Delta`, `Elo Change`, `ELO Change`;
- иначе считается как `текущий ELO - ELO следующего (более старого) матча`;
- для пятого матча нужен шестой — поэтому `RECENT_MATCHES_FETCH_LIMIT = 21`.

#### Faceit URL

`PlayerProfile.profile_url`:

- если `faceit_url` начинается с `http://` или `https://`, он используется;
- `{lang}` и `%7Blang%7D` заменяются на `en` без учёта регистра;
- иначе строится fallback:
  `https://www.faceit.com/en/players/<urlencoded nickname>`.

#### Максимальный ELO

Ищется в CS2-профиле и в корне ответа по полям:

- `max_faceit_elo`
- `max_elo`
- `highest_elo`
- `faceit_elo_max`
- `max elo`

Официальный Faceit Data API обычно не отдаёт максимальный ELO, поэтому блок часто отсутствует.

#### Сравнение игроков

`build_player_comparison(left, right)` возвращает `PlayerComparison` с семью метриками:

| Ключ | Подпись | Что сравнивается |
|---|---|---|
| `elo` | ELO | `profile.faceit_elo` |
| `winrate` | Винрейт | `lifetime.winrate` |
| `kd` | K/D | `lifetime.kd` |
| `hs` | HS% | `lifetime.headshots_pct` |
| `adr` | ADR | `form.avg_adr` |
| `streak` | Текущая серия | signed streak |
| `hours` | CS2 | `steam.cs2_hours` |

Правила:

- `delta = left - right`; положительное значение означает преимущество первого игрока.
- Победитель (`winner`) определяется только если известны **оба** значения; иначе `None`.
- Равенство даёт `winner="tie"` и `delta=0`.
- Для часов CS2 `higher_is_better=None`, победитель не определяется — это нейтральная метрика.
- Текущая серия кодируется числом: победы `> 0`, поражения `< 0`. Благодаря этому серия из 2 побед выигрывает у серии из 3 поражений.
- Метрика без обоих значений не считается сравнимой, но в форматтер всё равно передаётся — он покажет `—` для отсутствующей стороны.
- `PlayerComparison.has_data` истинно, если хотя бы у одного игрока есть хотя бы одно значение.

### 7.7. `bot/formatter.py`

Отвечает только за представление. Вход — `PlayerStats` или `PlayerComparison`, выход — Telegram HTML и клавиатура.

#### Порядок блоков

1. Шапка:
   - `🎮 <b><a href="...">Ник</a></b> 🇰🇿`
   - `🏅 Уровень 10 · 2345 ELO`
   - `📈 Максимальный ELO: 2600`
2. `🌍 Рейтинг`
3. `📊 Общая статистика`
4. `🔥 Форма за последние 20 матчей`
5. `🕹️ Последние 5 матчей`
6. `🗺️ Карты`
7. `💻 Steam`
8. `Обновлено HH:MM`

#### Общая статистика

Выводится:

- `• Матчей: N`
- `• Винрейт: 55% (20 матчей: 60% ↑)`
- `• K/D: 1.25 (20 матчей: 1.30 ↑)`
- `• HS%: 48%`
- `• Лучшая серия побед: 10`
- `• Текущая серия: 2 победы` / `3 поражения`

Тренды:

- сравнивается lifetime-значение со средним за последние матчи;
- `↑` — recent выше;
- `↓` — recent ниже;
- при равенстве стрелки нет;
- если одного из значений нет, суффикс не выводится.

Нюанс: подпись всегда говорит `20 матчей`, даже если реально проанализировано меньше.

#### Форма

- `• Средний K/D: 1.30`
- `• Средний ADR: 77.4`
- `• Средний K/R: 0.87`
- `• Средние килы: 20.5`
- `• Винрейт: 60%`
- `• Результаты последних 10 матчей: ✅❌✅❌...`

Результаты идут **от нового к старому**. Строка `Предыдущие 10` не выводится.

#### Последние 5 матчей

Формат:

```text
• de_mirage · 13:9 · 25/12/5 · +20 ELO
• de_dust2 · 7:13 · 15/20/3 · −18 ELO
```

Недостающие части опускаются. Отрицательное ELO форматируется с символом `−`.

#### Карты

Одна таблица всех карт:

```text
🗺️ Карты
🏆 de_mirage — 75% · 40 матчей
▫️ de_dust2 — 55% · 30 матчей
📉 de_inferno — 30% · 31 матч
⚠️ de_overpass — 90% · 12 матчей
<i>🏆 лучшие · 📉 слабые · ⚠️ меньше 30 матчей</i>
```

Маркеры:

- `🏆` — лучшая карта;
- `📉` — слабая карта;
- `⚠️` — меньше 30 матчей;
- `▫️` — нейтральная карта.

Символ `•` в таблице карт больше не используется. Легенда выводится только для присутствующих категорий.

#### Steam

```text
💻 Steam
• CS2: 1234.5 ч
• VAC: ✅ нет
```

При бане:

```text
• VAC: ⛔ бан (2 бана, 30 дн. назад)
```

Часы форматируются как целое число, если значение близко к целому, иначе с одним знаком после запятой.

#### Экранирование и лимит

- Ник, названия карт и URL экранируются для HTML.
- Ник обрезается до 64 символов, название карты — до 48, URL — до 512.
- Итоговый текст ограничен **4096 символами**.
- При превышении бот обрезает текст по последнему переводу строки и добавляет:
  `<i>Сообщение сокращено.</i>`
- Предполагается, что каждая строка содержит сбалансированные HTML-теги.

#### Меню и навигация

Форматтер выносит все клавиатуры в отдельные билдеры:

- `build_main_menu_keyboard()` — постоянное `ReplyKeyboardMarkup`:
  ```text
  [ 🔍 Найти игрока ] [ ⚔️ Сравнить игроков ]
  [ ℹ️ Помощь ]
  ```
  Использует `resize_keyboard=True`, `is_persistent=True` и placeholder «Выбери действие».
- `build_start_keyboard()` — inline-кнопки стартового экрана: `menu:find`, `menu:compare`, `menu:help`.
- `build_cancel_keyboard()` — кнопка «✖️ Отмена» с callback `menu:cancel`.
- `build_help_keyboard()` — кнопка «⬅️ В главное меню» с callback `menu:main`.

Тексты и callback-константы (`MENU_FIND_TEXT`, `MENU_COMPARE_CALLBACK` и т. д.) также живут в `formatter.py`, чтобы хендлеры и тесты не дублировали строки и не возникало циклических импортов.

#### Клавиатура

```text
[ Открыть профиль на Faceit ]
[ Обновить ]
[ ⚔️ Сравнить с другим игроком ]
```

Callback-data: `refresh:<SteamID64>` и `compare_with:<SteamID64>`. Обе строки укладываются в лимит Telegram 64 байта; `compare_with:` занимает 13 символов, SteamID64 — 17, итого 30 байт.

#### Сравнение: формат сообщения

`format_player_comparison()` выводит:

```text
⚔️ <b>Сравнение игроков</b>

1️⃣ <b><a href="...">Alpha</a></b> 🇰🇿
🏅 Уровень 10 · 2345 ELO
2️⃣ <b><a href="...">Beta</a></b> 🇷🇺
🏅 Уровень 9 · 2100 ELO

📊 <b>Ключевые показатели</b>
• ELO: <b>2345</b> 🏆 vs 2100 · Δ +245
• Винрейт: 55% vs <b>60%</b> 🏆 · Δ −5 п.п.
• K/D: <b>1.25</b> 🏆 vs 1.10 · Δ +0.15
• HS%: 48% vs <b>52%</b> 🏆 · Δ −4 п.п.
• ADR: <b>77.4</b> 🏆 vs 70.2 · Δ +7.2
• Текущая серия: <b>2 победы</b> 🏆 vs 3 поражения · Δ +5
• CS2: 1234.5 ч vs 2100 ч · Δ −865.5 ч

<i>🏆 — лучший показатель · Δ — разница (1-й минус 2-й)</i>

<i>Обновлено 15:42</i>
```

Правила форматирования:

- лучший показатель выделяется `<b>...</b> 🏆`;
- при равенстве оба значения остаются без маркера;
- отсутствующее значение выводится как `—`;
- `Δ` форматируется в единицах метрики: ELO и серия — целые, K/D — 2 знака, ADR и часы — 1 знак, винрейт и HS% — процентные пункты;
- знак минуса — типографский `−`;
- строка с двумя отсутствующими значениями пропускается;
- если не осталось ни одной строки — выводится `Недостаточно данных для сравнения.`;
- легенда `🏆` показывается только если хотя бы одна метрика имеет победителя;
- часы CS2 — нейтральная строка без `🏆`;
- ник и URL экранируются; итог ограничен 4096 символами.

Клавиатура сравнения:

```text
[ 1. Alpha ] [ 2. Beta ]
[ 🔄 Обновить сравнение ]
```

Callback-data: `refresh_compare:<SteamID64_left>:<SteamID64_right>` — 51 символ, что укладывается в лимит Telegram (64 байта).

## 9. Устойчивость и обработка ошибок

Проект спроектирован так, чтобы одна недоступная часть API не ломала весь ответ.

### Обязательные данные

- Профиль игрока.
- Хотя бы один из двух источников: lifetime или recent matches.

Если оба источника упали — пользователь получает сообщение об ошибке.

### Необязательные данные

- Рейтинг страны/региона.
- Steam-статистика.
- Детали конкретных матчей.
- Максимальный ELO.

Их ошибки:

- логируются;
- не пробрасываются;
- соответствующий блок просто не выводится.

### Сравнение

- Ошибки загрузки изолированы по сторонам через внешний `gather(return_exceptions=True)`.
- Если один игрок не найден, второй всё равно загружается, но сравнение не строится: пользователю показывается, какая сторона недоступна.
- 429 хотя бы у одной стороны → сообщение о лимите Faceit; при известном `retry_after` добавляется время повтора.
- Если оба игрока не найдены → `Ни у одного из игроков нет Faceit-аккаунта с CS2.`
- Если обе загрузки упали с другими ошибками → общее сообщение об ошибке.
- Если оба профиля загрузились, но ни одной общей метрики нет → `Недостаточно данных для сравнения игроков.`
- Совпадение SteamID64 отсекается до сети; совпадение Faceit `player_id` — после загрузки.
- Невалидный callback обновления обрабатывается всплывающим ответом без падения.
- Обновление сравнения точечно инвалидирует кэш обоих игроков и повторяет загрузку; при активном cooldown обоих сразу отвечает, что данные свежие.

### Лимиты и защита квоты Faceit

- `RateLimitMiddleware` ограничивает действия на `user_id` взвешенным скользящим окном: по умолчанию 10 единиц за 60 секунд.
- Обычный поиск стоит 1, сравнение и refresh — 2. `/start`, `/help`, `/cancel`, кнопки меню и текстовые команды отмены FSM («Отмена», «отмена», `/cancel`) исключены и не расходуют лимит.
- `RateLimitMiddleware` регистрируется на `dp.message.outer_middleware` и `dp.callback_query.outer_middleware`; `refresh_cooldown` и `faceit_client` передаются через workflow data `Dispatcher`. Если `faceit_client` не передан, `create_dispatcher` логирует предупреждение при старте.
- При превышении middleware один раз отвечает «Слишком много запросов, подожди N сек», дальше молча пропускает события до конца окна. Callback всегда получает `answer()`, чтобы сбросить спиннер.
- Устаревшие записи лимитера периодически удаляются; всё хранится в памяти процесса.
- `RefreshCooldown` не даёт обновлять данные одного игрока чаще раза в 60 секунд. Для сравнения cooldown проверяется по каждому SteamID64: блокирует, если обновлялся хотя бы один участник. Перестановка A/B или замена второго игрока не обходит ограничение.
- Для refresh cooldown резервируется сразу после проверки, до первого `await`, поэтому два параллельных refresh одной цели дают только одну загрузку. При `FaceitError` или другом исключении резерв снимается через `release()`; первичный показ профиля/сравнения ставит отметку после успешной отправки.
- Время загрузки фиксируется и при первичном показе профиля или сравнения, поэтому «Обновить» сразу после показа не тратит квоту.
- `FaceitClient` объединяет одинаковые одновременные запросы (single-flight), ограничивает параллелизм (5), пропускает сетевые запросы через token bucket `FACEIT_MAX_REQUESTS_PER_SECOND` (4 запроса/сек до семафора) и после 429 включает глобальный cooldown.
- Глобальный cooldown = `max(Retry-After, FACEIT_RATE_LIMIT_COOLDOWN_SECONDS)` с потолком `FACEIT_RATE_LIMIT_COOLDOWN_MAX_SECONDS` (300 с).
- Повторов на 429 нет: клиент сразу выбрасывает `FaceitRateLimit`, поэтому пользователь получает сообщение о лимите с известным временем ожидания без скрытого `sleep`.
- Кэшированные ответы обслуживаются при активном cooldown и не расходуют токены token bucket; квота Faceit на них не тратится.
- Детали завершённых матчей не инвалидируются при refresh игрока, поэтому повторная загрузка профиля делает меньше HTTP-запросов.
- Негативный кэш 404 по поиску игрока живёт 60 секунд и сбрасывается точечной инвалидацией.
- При закрытии `FaceitClient.aclose()` отменяет и дожидается незавершённых single-flight задач, затем закрывает HTTP-соединения.

### Меню и FSM

- FSM использует `MemoryStorage`: состояние живёт только в памяти процесса и теряется при рестарте.
- `/start`, `/help`, `/compare`, нажатие кнопок меню и отмена очищают состояние, поэтому «зависших» шагов не остаётся.
- Если данные FSM потеряны или повреждены, второй шаг отвечает «Сессия сравнения устарела» и предлагает начать заново.
- Невалидный ввод на шаге сравнения не сбрасывает сценарий: бот просит ссылку ещё раз.
- Callback-экраны редактируют сообщение; при `message is not modified` ошибка игнорируется, при прочих ошибках отправляется новое сообщение.
- Если `faceit_client` не настроен, кнопки меню и `/compare` сообщают об этом без перехода в FSM.

### Прочее

- 404 при поиске игрока → «нет Faceit-аккаунта с CS2».
- 404 при рейтинге или деталях матча → `None`.
- 429 (сразу, без повторов) или активный глобальный cooldown → отдельное сообщение о лимите с известным временем повтора.
- Сетевые ошибки Faceit → общее сообщение об ошибке.
- Неожиданные исключения в хендлере → `logger.exception` и безопасный ответ пользователю.
- Детали матчей загружаются параллельно; ошибка одного матча не мешает остальным.

## 11. Текущие ограничения и нюансы

1. **Нет базы данных.** История матчей и графики прогресса потребуют отдельного хранилища; сравнение работает без БД.
2. **Кэш только в памяти.** После рестарта он пуст; несколько инстансов бота не разделяют кэш.
3. **Лимиты и cooldown только в памяти процесса.** При нескольких инстансах бота они не разделяются, как и кэш.
4. **Нет фоновой очереди.** Тяжёлые запросы выполняются прямо в обработчике.
5. **Только long polling.** Webhook, Docker, CI и деплой-конфиги отсутствуют.
6. **Только CS2.** Другие игры Faceit не поддерживаются.
7. **Голый SteamID64/vanity в обычном сообщении не обрабатывается.** `resolve_steam_id` их понимает, но `handle_link` сначала требует `http(s)`-ссылку. Исключение — `/compare` и пошаговое сравнение, где голые идентификаторы принимаются.
8. **Подпись тренда всегда «20 матчей».** Даже если реально загружено меньше матчей.
9. **Последовательность результатов может быть короче 10.** Если API не отдал `Result` для части матчей, а подпись остаётся «последних 10».
10. **Максимальный ELO часто недоступен.** Официальный Faceit Data API обычно не отдаёт это поле, поэтому блок часто пропускается.
11. **Время внизу — локальное время сервера.** Часовой пояс пользователя не учитывается.
12. **Обрезка сообщения по переводу строки.** В редком случае одной очень длинной строки теоретически можно разорвать HTML-разметку.
13. **Steam-статистика требует публичного профиля и ключа.** При закрытом профиле блок просто исчезает.
14. **Нет локализации.** Все тексты на русском, i18n не предусмотрен.
15. **Сравниваются только два игрока.** Больше двух ссылок отклоняется.
16. **Сравнение требует обоих игроков.** Если один не найден, показывается ошибка, а не статистика второго.
17. **Часы CS2 в сравнении нейтральны.** Больше часов не означает «лучше»; победитель по этой метрике не определяется.
18. **Серия сравнивается как signed-число.** Победы считаются положительными, поражения — отрицательными; это осознанное упрощение, а не отдельная оценка силы серии.
19. **FSM не переживает рестарт.** Незавершённое пошаговое сравнение после перезапуска бота придётся начать заново; внешнего хранилища состояний нет.
20. **Постоянное Reply-меню устанавливается через `/start`.** Если пользователь очистил чат или скрыл клавиатуру, вернуть её можно командой `/start`; inline-экраны меню сами Reply-клавиатуру не переустанавливают.

## 12. Возможные направления развития

1. **История и графики.** Сохранять матчи в SQLite/PostgreSQL и строить динамику ELO, K/D и винрейта.
2. **Сравнение более двух игроков.** Сводная таблица на 3–5 участников.
3. **Кэш в БД.** Переживать рестарты и разделять данные между инстансами.
4. **Распределённые лимиты и очередь.** Вынести in-memory лимиты в Redis и добавить фоновую очередь для более равномерной нагрузки на Faceit API.
5. **Webhook + Docker + CI.** Production-развёртывание и автоматические проверки.
6. **Настройка часового пояса и языка.** Пользовательские preferences.
7. **Больше Steam-данных.** Например, время за последние две недели, количество игр, другие баны.
8. **Аналитика по последним матчам.** Винрейт и K/D не за всю жизнь, а за последние 20/50 матчей.
9. **Поддержка других игр Faceit.** Не только CS2.
10. **Исправление ввода без URL.** Пробовать `parse_steam_input` на всём тексте обычного сообщения, если URL не найден.
11. **Более точные подписи трендов.** Писать фактическое число проанализированных матчей вместо статического «20 матчей».
12. **Кнопка «Обновить» с индикатором загрузки.** Сейчас есть только `typing`-action и всплывающий ответ callback.
13. **Расширенное сравнение.** Добавить рейтинг страны/региона, winrate за последние матчи и разбивку по картам.
14. **Внешнее хранилище FSM.** Redis или другое key-value-хранилище, чтобы пошаговое сравнение переживало рестарт и работало в нескольких инстансах.

## 13. Итог

Это аккуратно разделённый на слои, полностью асинхронный Telegram-бот с:

- надёжным клиентом Faceit API с ретраями, single-flight, семафором и TTL-кэшем;
- отдельным Steam-модулем;
- продуманной бизнес-логикой расчётов;
- отдельным слоем сравнения двух игроков с параллельной загрузкой и изоляцией ошибок;
- постоянным Reply-меню, стартовым inline-экраном и пошаговым FSM-сравнением;
- устойчивым форматированием HTML с экранированием и лимитом Telegram;
- хорошим покрытием тестами без реальных сетевых запросов.

Основной сценарий полностью рабочий: ссылка → SteamID64 → Faceit-профиль → статистика CS2 → HTML-сообщение с картами, формой, последними матчами, рейтингом и Steam-блоком.

Сценарий сравнения: «⚔️ Сравнить игроков» (два шага FSM), «⚔️ Сравнить с другим игроком» под профилем (сразу второй шаг), `/compare url1 url2` или две ссылки одним сообщением → параллельный резолвинг → параллельная загрузка двух профилей → расчёт семи метрик и победителей → компактная HTML-таблица с 🏆 и `Δ` → кнопки профилей и обновления сравнения.
